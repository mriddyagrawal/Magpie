Benchmark report · 2026-09-01

Prompt Ordering on LFM2.5-VL

Does moving the question before the image, or repeating it after, change what a 3B vision–language model gets right? Across 500 paired POPE items, no — and the one ordering that did move something moved the wrong thing.

LFM2.5-VL-3B · Q6_K llama.cpp 10502 · 0adcc3bb5 Metal · M1 Max POPE random · n=500 greedy · T=0 1500 generations · 18.9 min

The comparison that mattered

SIT → STIT is a null result. Repeating the question after the image changed accuracy by exactly zero.

Six of 500 items flipped, three in each direction, cancelling perfectly. McNemar p = 1.0000; bootstrap 95% CI [−0.010, +0.010]. This is the outcome you predicted, and it is consistent with three of the five models in arXiv 2607.15565.

STI → SIT is also null — but worth reading, because the sign runs against the hypothesis. Putting the question first, the arrangement that is supposed to let attention pre-select the relevant image regions, scored lower (0.8960 vs 0.9080), not higher. The gap is not statistically distinguishable from zero, so the honest reading is “no effect,” not “question-first hurts.” But nothing here supports question-first helping.

01What was compared

Three arrangements of the same three components inside one user turn, generation beginning after the last element. Content is byte-identical across arms; only position changes.

The blank-image control is the load-bearing one. A silently dropped image would produce a plausible-looking table where all three arms scored the same — a null result for entirely the wrong reason. Substituting a grey frame collapses accuracy to 0.458 and drives the model to answer “no” to every question, which is the correct behaviour when there is nothing in the picture. The image is doing the work.

Token order was controlled at the chunk level through llama.cpp's mtmd library rather than through a chat template, so the image sits exactly where the marker was placed. The template was inspected too: LFM2.5-VL's parse_content macro iterates the content list in order and concatenates, with no image hoisting — so the model card's written example and the code samples were never in conflict, they simply show two different orderings.

04The ordering did change the model — just not its answers

The most interesting number in this report

STI produced a capitalized Yes/No on 96.4% of items. SIT produced capitalized output on 2.0%. STIT landed in between at 25.0%. Same system prompt, same question, same image — only position changed.

This matters for interpreting the null. A sceptic's first objection to “ordering doesn't matter” is that the manipulation never really took hold — that 156 tokens rearranged is too weak an intervention to shift a 3B model. The capitalization split refutes that directly. Moving the question across the image swings the surface form of the answer almost completely, from 96% capitalized to 2%. The intervention is potent. It simply expends its effect on formatting rather than on correctness.

A useful way to hold the result: prompt ordering here is a style variable, not a grounding variable. If you are parsing model output with a case-sensitive matcher, ordering will absolutely break you. If you are relying on it to make the model see the picture better, it will not.

05Outliers: what the 18 flips have in common

The STI → SIT discordant set is small but strikingly lopsided. 15 of 18 have gold answer “yes.” The dominant failure is STI answering “no” about an object that is genuinely present.

The entire STI deficit is false negatives — 45 against SIT's 38, with false positives essentially unchanged at 7 vs 8. Reading the question first made the model more conservative, not more perceptive. It says “no” more often, and since POPE's gold set is 48.8% yes, extra conservatism costs accuracy.

The objects concentrate tellingly: dining table (4 of 18), truck (3), chair (2). These are the large, backgrounded, partially-occluded category — things present in a scene without being its subject. A dining table is often visible only as an edge under the plates. That is exactly the population where a marginal shift in visual attention tips a borderline logit, and where the question-first arrangement apparently primes the model to look for a salient, foregrounded instance and answer “no” when it doesn't find one.

Worth noting against over-reading this: all 18 flips sit on 18 distinct images, so no single photo is driving the pattern. But 18 items is a small set, and the object concentration could easily be chance. It is a hypothesis for a follow-up, not a finding.

All three arms show a negative yes-bias — they under-predict “yes” relative to gold. This is worth flagging because it inverts POPE's best-known failure mode, where models typically over-answer “yes.” LFM2.5-VL-3B at Q6_K is unusually conservative on this benchmark.

06What else could explain these numbers

What the design rules out

  • Content differences between arms. Ruled out by the anagram assertion holding on all 500 items at the token-ID level, not merely the count.
  • Image preprocessing drift. Image-token counts vary across items (128–256, dynamic resolution) but are identical across arms within every item.
  • Sampling noise. Greedy decoding with a bare argmax sampler; no top-k, top-p, or penalties in the chain. Every discordant pair is attributable to the prompt.
  • Batching non-determinism. Single stream, fixed n_batch/n_ubatch, identical context params across all three arms, KV cleared between items. Floating-point reduction order is held constant, so no flips come from the scheduler.
  • Scoring error. Zero escalations: the complete set of distinct outputs across all 1500 generations is {Yes, No, yes, no}. Nothing required interpretation, so no judging bias could enter.
  • Prompt tuning toward a winner. One system prompt, written once before any results were seen, never revised.

What remains genuinely uncertain

  • Statistical power. This is the real limitation. At the observed discordance rates, n=500 can only resolve differences of roughly ±0.012 to ±0.024. Effects smaller than about two points are invisible here. “No detectable effect” is the correct claim; “no effect” is stronger than the data supports. For scale, three of the five reference models had effects inside that blind spot (−0.001, −0.003, +0.010).
  • Quantization. Run at Q6_K, deliberately, because that is what ships. Quantization noise is roughly the same magnitude as the effect being hunted, so a bf16 run could plausibly land differently.
  • POPE's binary format. A 50% floor compresses effect sizes. If ordering helps by sharpening localization, a yes/no task may be too coarse to register it. A short free-form set — GQA or TextVQA — would give an ordering effect more room to appear.
  • Annotation error. POPE is known to carry label noise (see RePOPE, arXiv 2504.15707). Some of the 45 STI “false negatives” may be correct answers against wrong labels, which adds noise to an already small discordant set.
  • Image-level correlation. 500 questions drew on 333 unique images, up to 4 questions each. The bootstrap resamples questions rather than images, so its interval is very slightly optimistic.
  • Greedy only. Ordering effects could differ once sampling smears the distribution — and greedy is not what Magpie ships.

07What this means

On LFM2.5-VL-3B at Q6_K, prompt ordering is not an accuracy lever. Neither moving the question ahead of the image nor repeating it afterwards produced a change distinguishable from zero, and the one directional hint present runs opposite to the attention-priming hypothesis.

That has a practical consequence worth more than the accuracy numbers. Since ordering costs nothing in accuracy, the arrangement is free to be chosen on engineering grounds — and image-first (SIT) is the one that lets an image prefix be KV-cached across many questions about the same picture. The ordering that is cheapest to serve is also, here, the one that scored highest. There is no trade-off to manage.

The finding that should actually change behaviour is the capitalization split: if anything downstream matches on "Yes" case-sensitively, prompt ordering will silently break it.
